# 科学验证

先写独立检查脚本，再通过 run --stage verify 执行。检查不能只读取模型写下的“通过”文字。
重算结果指标、单位和约束；检查公式与代码一致性、基线比较、边界、敏感性以及所有小问覆盖。

- 优化：独立核算约束/目标，小规模枚举或有效界；说明最优性证据。
- 预测：无数据泄漏、固定划分、公平基线、误差与适用范围。
- 仿真：重复试验、种子、统计波动、极限情形。
- 评价：指标方向、尺度、冗余、权重和排名稳定性。
- 理论：前提、每一步推导、反例/边界；数值检查不构成证明。

verification.json 结构如下。checks 每条记录一个真实检查，evidence 是项目内实际证据文件。
计算题让实际检查脚本生成此 JSON，并将它作为 run 的 --output。
失败检查填写 fail 或 inconclusive，complete 会拒绝；定位原因后 reopen 对应阶段修复。

```json
{
  "verdict": "pass",
  "checks": [
    {"name": "约束和目标独立重算", "status": "pass", "evidence": ["results/checks.json"], "detail": "说明方法、容差与实测结果"}
  ],
  "limitations": ["检查未覆盖的适用范围"]
}
```

不要照抄示例的通过状态。脚本只校验结构、摘要和执行关联，不判断检查逻辑是否正确。
理论题可以使用人工推导证据而不强求命令执行；此时明确它是 Agent 复核，不能宣称独立形式证明。
报告中的关键结论须定位到实验/证明证据；假设、推测和计算事实分别表达。

## 小问覆盖与结论审查

读取 [结论证据审查](claims.md)，在 verification.json 的检查说明或单独登记的 claim-review.md 中给出主张、证据和适用范围。该审查补充数值核验，不能用模型的判断替代实际检查。

逐项对照 problem.md 的原文要求和模型实现表，确认所有必答项都有结果或明确的未解说明。共享参数、单位、样本筛选和关键数字在代码、结果、图表与论文间应一致；发现差异时回到产生差异的阶段修正。

检查指标时使用其定义和适用条件，不能只套范围规则。例如测试集 R² 可以为负，常量目标也可能使其未定义；优化器终止不等于已证明全局最优；归一化强制得到的性质不能宣传为模型发现。
