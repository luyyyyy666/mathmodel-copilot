# 赛事格式配置

理解阶段识别赛事与用户交付要求，写作前确认格式，交付前对照实际 PDF。配置由宿主 Agent 读取并应用；目前没有脚本自动据此生成版式或判定赛事合规。

可将 [配置模板](../assets/worksheets/contest-profile.json) 复制为题目目录的 contest-profile.json，在 understand 阶段作为额外产物登记。简单任务也可把同样信息放进 problem.md。无需赛事交付时使用 generic，保留用户明确要求即可。

## 核实要求

记录赛事、年份、组别、题号和规则版本。每条要求保存来源 URL 或本地原件位置、页码/段落、访问日期及核验状态。区分官方规则、用户偏好与本项目排版选择；用户定制偏离官方要求时明确标成定制交付，不声称符合该赛事。

`null` 表示尚未确定，不表示无限制。`requirements` 中每条使用 `id`、`value`、`scope`、`status`、`source`、`locator`、`checked_on`；status 可为 verified、unverified 或 not_applicable。实际需要的要求包括：

- 页数上限及哪些页面计入；若存在下限则单独记录，不能把上限解释成最低目标。
- 摘要页、队伍标识、匿名范围、页眉页脚、字号、纸张和边距。
- 是否需要目录、附录、代码、数据、单独的备忘录或信件。
- 引用格式、AI 使用说明、文件类型、文件命名与大小限制。

只在规则确实提出该要求时将其作为必需项。规则不可访问但可以继续解题时，先保留 unverified 并推进计算；格式完成时指出未核实项，不编造合规结论。

## 内容骨架的选择

下表是写作起点，不是任何年份的官方模板。当前包自有的通用 LaTeX 主文件负责基础排版，宿主根据配置生成相应章节并调整主文件。

| profile | 可采用的内容骨架 | 应单独核实 |
|---|---|---|
| generic | 摘要、问题与假设、方法、结果与验证、局限、引用 | 用户语言与交付格式 |
| cumcm | 摘要与关键词、问题分析、假设与符号、按小问建模求解、检验、评价 | 当届匿名和文件组成；目录、页眉等不凭模板默认 |
| mcm_icm | Summary、背景与问题、假设与符号、模型及逐问结果、验证与评价 | Summary Sheet、Team Control Number、计页范围、题目要求的附加文书 |
| statistical | 中/英文摘要按需、研究问题、数据、方法、实证结果、讨论与建议 | 组别格式、摘要语言、编号方式和附录；不默认必须致谢 |

多小问可以共用方法章节，但每项要求都要有可定位的回答。页数不足不自动扩写，页数过多优先删重复推导和无信息图表；保留足够证据，不用极小字号挤入内容。

## 应用和最终核对

根据已核验要求在项目内修改主文件、摘要布局和章节；沿用项目内字体嵌入与 Unicode 检查。版式调整后真实编译，按规则 scope 统计页数并检查身份信息、附件、引用、AI 说明及文件命名。

在交付说明记录“要求—来源—实测结果—证据位置—通过/失败/未核实”。仅写一份配置不算完成合规检查。配置变更会影响已登记产物时，用 reopen 从相应上游阶段重新登记并重建论文；不要直接覆盖冻结的规则记录。
