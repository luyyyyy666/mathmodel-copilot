# 结果能支持什么结论

在 verify 阶段、写论文前使用；结果或表述变更后重新核对。可将 [审查模板](../assets/worksheets/claim-review.md) 合并到验证报告，或保存为 claim-review.md 并作为 verify 产物登记。

## 按主张检查证据

从每个小问的拟回答内容和最重要的建议出发，给主张编号 C1、C2。记录具体表述、关联 Q 编号、结果文件/字段或推导位置、比较协议、适用范围，以及可能推翻它的证据。

检查是否存在不公平基线、训练评价混用、不可识别参数、未测量的混杂因素、只报告成功实验或不确定性被忽略。优先挑战会影响最终建议的假设；不是对每题机械执行所有统计检验。

以证据决定下一步：

| 证据关系 | 如何处理 |
|---|---|
| 支持 | 使用与实验/证明范围一致的表述，保留条件和局限 |
| 部分支持 | 写清已支持部分；补关键实验，或收窄主张后重新审查 |
| 不支持 | 撤回该主张，检查模型/实现或考虑替代方案 |
| 无法判断 | 标明缺失数据、精度或核验，不把不确定写成正面结论 |

这些是内容审查结论，不是 verification.json 的新状态枚举。数值检查仍使用既有 pass/fail/inconclusive。发现真实失败不能靠修改措辞改成 pass；修正模型、代码或实验时 reopen 相应阶段。仅收窄外推范围时保留原主张及变更理由，再确认修改后的回答是否满足原题。

题目要求全局最优，而目前只有可行解时，可以交付阶段结果及最优性缺口，但不能把缩小后的回答宣称为完整解题。若无法补齐必答项，应明确报告未完成部分。

## 示例：从结果到适当表述

- 一个固定测试集上误差下降，只支持该评价协议下的比较，不支持“所有场景都优越”。记录样本规模、差值与不确定性。
- 优化得到更低的目标值，先核对可行性和求解状态；没有有效界或证明时不写“全局最优”。
- 改变假设参数后结果变化，属于情景分析；不能当成观测证据或因果干预效果。
- 边界算例符合推导，只能作为检查；理论命题仍需证明全部前提下成立。

由宿主 Agent 基于实际产物完成审查；不要求另一个模型、固定评委数量或自评分数。复核者应说明做了哪些重算或推导核对，不能用角色名称制造“独立验证”的印象。
